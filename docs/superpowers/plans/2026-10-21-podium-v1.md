# Podium v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Podium v1, a standalone macOS Stage Manager replacement whose strip can sit on the left or right, feels Apple-made, and never loses a window.

**Architecture:** A Swift package with two targets. `PodiumCore` is pure logic with no AppKit: the stage model, strip and pile layout, the velocity-preserving spring engine, the parking ledger and recovery, auto-hide/hover state machines, minimize decisions, and transition plans. It is test-first and covered by `swift test`. `Podium` is the AppKit app: Accessibility window control, ScreenCaptureKit thumbnails, a click-through overlay that draws window cards driven by the spring engine, a non-activating strip panel, the minimize event tap, and the menu bar. The structure mirrors Apple's: one model → pure layout → animated transitions.

**Tech Stack:** Swift 6.4 toolchain (Command Line Tools, no Xcode), SwiftPM, swift-testing (`import Testing`), AppKit, Core Animation, ApplicationServices (AX), ScreenCaptureKit, CoreGraphics event taps.

**Spec:** `docs/superpowers/specs/2026-10-21-podium-design.md` (also read `docs/research/2026-10-21-stage-manager-internals.md`)

## Global Constraints

- Permissions: Accessibility and Screen Recording only. No SIP changes, no Dock changes, no system extensions.
- Minimum macOS: 14.0 (ScreenCaptureKit screenshot API, `NSScreen.displayLink`). Owner runs macOS 27.2 on Apple Silicon.
- Allowed private API: `_AXUIElementGetWindow` only (SIP-free, used by AltTab/Rectangle). Anything else needs a public fallback and owner sign-off.
- v1 runs on the main display only; every model type carries a display ID so multi-display needs no rewrite.
- Strip side: `left` or `right`. Top/bottom are out of scope.
- Hide a parked window by moving it so only a 1-pt corner stays on screen (bottom-right of its display). Never minimize or app-hide to park.
- Write the ledger entry **before** moving a window off-screen; remove it only **after** the window is confirmed back on-screen.
- Bundle ID `dev.podium.Podium`, app name `Podium`, menu bar app (`LSUIElement` true).
- Language mode: `PodiumCore` Swift 6; `Podium` app target Swift 5 mode (AppKit/AX interop).
- Every build is signed with a stable identity (see Task 1) so permissions survive rebuilds.

## Review Focus

1. **The app that owns a parked window quits.** Its ledger entries must be dropped quietly on the next recovery or restore, with no AX calls on dead windows → test in Task 5 (`recoveryDropsWindowsThatNoLongerExist`).
2. **A window refuses or clamps the off-screen move** (some apps keep windows on-screen). The window must stay on stage and be treated as not parked, never half-hidden → test in Task 8 (`parkFailsWhenWindowDoesNotLeaveScreen`).
3. **The display changes while windows are parked** (unplug, resolution change). Restored windows must land fully on a visible screen → test in Task 5 (`recoveryClampsFramesOntoVisibleScreen`).
4. **Sheets, dialogs, panels, full-screen and minimized windows.** These must never be managed or parked → test in Task 3 (`unmanageableWindowsAreIgnored`).
5. **macOS disables the event tap** (slow tap timeout) or the hit-test is ambiguous. Minimize must pass through to normal behavior, never be swallowed unhandled → test in Task 7 (`passesThroughWhenTapUnhealthy`).

- `minimize(w)`: move `w` to a new non-active stage at the front of the strip; if the active stage becomes empty, `activeStageID = nil`.
